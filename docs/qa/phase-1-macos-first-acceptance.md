# Phase 1 QA Baseline — macOS-first

## 结论先行

Phase 1 的 QA 口径已切换为 **macOS 首发优先**。当前仓库仍处于“Flutter 壳子 + 静态列表”阶段，**尚不具备 Phase 1 业务验收条件**。现阶段 QA 的目标不再是泛化多端兼容，而是把桌面主路径先打通：

1. macOS 能稳定启动
2. 桌面信息架构和布局可用
3. 键盘流完整可走
4. Today / Inbox 主路径闭环成立
5. 低打扰提醒可验证
6. AI 输入可在桌面端结构化落任务

---

## 当前基线判断

基于现有代码与文档：

- 现有入口仅有 `apps/mobile/lib/main.dart`
- UI 仍是静态 `HomePage + ListView + FAB`
- 没有路由、状态管理、持久化、提醒、AI 解析、任务数据模型扩展
- README 明确指出 `macos/` 等 Flutter 平台目录尚未生成

**QA 判定：当前只能算“代码壳存在”，不能算“macOS 首发版本可验收”。**

---

## macOS-first 验收重点（替代旧的多端并行口径）

### A. macOS 可启动性（P0）

必须满足：

- 仓库可在 macOS 本机完成 `flutter pub get`
- 已生成并提交或可稳定生成 `macos/` 平台工程
- 执行 `flutter run -d macos` 可启动，不因缺失平台目录/配置而失败
- 冷启动进入主界面时间可接受，无白屏/崩溃/卡死
- 二次启动稳定，无首次启动后再打开崩溃问题

验收失败即 **P0 阻断**：

- 没有 `macos/` 工程
- 需要人工修脚本才能启动
- 启动即崩溃或进入空白页
- 主窗口尺寸异常、窗口内容裁切严重

### B. 桌面布局（P0）

首发必须按桌面使用习惯设计，而不是简单把移动端单列页面放大。

必须满足：

- 默认窗口尺寸下（建议 1280×800 级别）核心区不拥挤、不漂移
- 左侧导航 / 主列表 / 详情或输入区的信息层级清楚
- Today、Inbox、任务详情/创建入口在首屏可见
- 关键 CTA 不依赖悬浮按钮作为唯一入口
- 空状态、加载态、错误态都有明确桌面反馈
- 在窗口缩放后仍可用，不出现主要控件遮挡、溢出、不可点击

验收失败即 **P0 阻断**：

- 仍是纯移动端 Scaffold 直接放大
- 关键入口只能鼠标点 FAB 才能触达
- 窗口缩小时主内容断裂
- Today / Inbox 在主路径中不显性

### C. 键盘流（P0）

macOS 首发必须把键盘效率当主交互，不是补充项。

必须满足：

- 全局或页面级快捷键有定义，至少覆盖：新建任务、搜索/聚焦输入、切换 Today、切换 Inbox、完成/保存、取消/关闭
- Tab 顺序合理，可在主要可操作控件间流转
- 输入框聚焦后可直接录入，不要求先额外点击多次
- 回车 / Cmd+Enter / Esc 等关键行为语义一致
- 焦点状态可见，不能“看不出当前在哪”

验收失败即 **P0 阻断**：

- 主流程必须依赖鼠标完成
- 焦点乱跳或无法从侧栏切到主区
- 快捷键与界面行为冲突
- 弹层打开后 Esc 不能关闭 / 回车误提交

### D. Today / Inbox 主路径（P0）

这是桌面首发的最短价值闭环，必须先成立。

必须满足：

- 用户可以快速进入 Inbox
- 可从 Inbox 新建任务并保存
- 可把任务标记到 Today 或让 Today 视图可见当天待办
- Today 与 Inbox 的切换成本低（导航清晰，最好支持快捷键）
- 任务的基础信息至少包含：标题、状态、时间归属（Today/Inbox/未安排）
- 主路径的数据在刷新或重启后不丢失

验收失败即 **P0 阻断**：

- Today / Inbox 只是文案，没有真实数据视图
- 新建后数据不持久
- Today 和 Inbox 关系不清，用户无法判断任务去哪了

### E. 低打扰提醒（P1，首版必须给出最小闭环）

提醒不要求一步到位做复杂通知系统，但不能完全缺位。

最低要求：

- 用户可为任务设置“需要提醒 / 不提醒”或基础提醒时间
- 提醒行为符合低打扰原则：不频繁抢焦点、不弹出连续打断式模态
- 若系统通知暂未接通，至少要有应用内提醒占位策略和状态说明
- 提醒失败时，用户知道发生了什么，而不是静默丢失

P1 失败表现：

- 完全没有提醒入口
- 提醒开关存在但无任何实际反馈
- 提醒以强干扰方式抢占输入流程

### F. AI 输入 → 任务结构化闭环（P0）

这是产品差异化主路径，Phase 1 可以做小，但不能没有闭环。

必须满足：

- 桌面端存在明确 AI 输入入口（输入框/面板/快速捕获区）
- 用户输入自然语言后，系统能生成结构化任务草案
- 至少能抽出：任务标题；建议归类到 Inbox 或 Today；可选的时间信息
- 用户可在落库前确认/编辑
- 确认后任务真正进入列表，而不是只显示解析结果
- 失败时给出可理解的降级路径（例如转为普通文本任务）

验收失败即 **P0 阻断**：

- 只有“AI 稍后接入”提示
- 只有输入框，没有结构化结果
- 解析结果不能进入真实任务列表
- AI 失败直接吞掉输入内容

## P0 / P1 验收门槛

### P0（未满足即不允许宣称 Phase 1 可验收）

1. **macOS 可启动**
   - `flutter run -d macos` 成功
   - 无启动崩溃
2. **桌面主布局成立**
   - 非移动端拉伸版
   - Today / Inbox / 输入或详情区可见
3. **键盘主路径可用**
   - 新建、切换、保存、取消有稳定键盘操作
4. **Today / Inbox 数据闭环成立**
   - 可创建、查看、切换、持久化
5. **AI 输入到结构化任务闭环成立**
   - 可输入、解析、确认、入列

### P1（P0 后立即跟进，影响可用性与口碑）

1. 低打扰提醒最小闭环
2. 空态/错态/加载态完善
3. 基础搜索/过滤（若已设计进主路径）
4. 窗口尺寸变化下的布局稳定性
5. 基础性能：列表交互、输入响应、保存反馈不迟滞

## Dev 需要补齐的前置项

以下项不补齐，QA 无法进入有效验收：

### 1. macOS 工程与运行前置

- 生成并提交 `macos/` 平台目录，或给出稳定生成方式
- 明确 Flutter 版本、Dart 版本、运行命令
- 提供一条可复现的本地启动说明

### 2. 桌面 IA 与交互稿最小定义

- 明确桌面主窗口分区：导航、主列表、详情/输入区
- 明确 Today / Inbox 的信息关系
- 明确 AI 输入入口放在哪里，不接受“先用 FAB 顶一下”

### 3. 任务领域模型最小闭环

至少补齐：

- id
- title
- status
- bucket（Today / Inbox / other）
- reminder metadata
- createdAt / updatedAt
- AI 解析结果到任务实体的映射规则

### 4. 状态管理与持久化

- 不能继续停留在 `main.dart` 里静态数组
- 需要至少一种本地持久化方案
- 重启后 Today / Inbox 数据必须保留

### 5. AI 解析接口或本地 stub 协议

- 即使正式模型未接通，也要提供稳定 stub
- 输入、输出、失败态的数据结构要固定
- QA 需要可重复验证解析结果，而不是随机不可控演示

### 6. 提醒策略说明

- 若首版不接系统通知，需明确应用内提醒策略
- 若接系统通知，需明确权限、触发、失败回退

---

## 建议的验收执行顺序

1. 先卡 `macOS 启动成功`
2. 再卡 `桌面布局 + Today/Inbox 可见`
3. 再卡 `键盘流`
4. 再卡 `Today/Inbox 创建与持久化`
5. 最后卡 `AI 输入结构化闭环`
6. 低打扰提醒作为 P1 紧跟补齐

原因：当前仓库离“业务可验收”还有明显距离，先把运行面与主路径打通，能最快暴露真正阻断项。

### 已完成

- 已将 Phase 1 QA 口径纠偏为 **macOS-first**，不再按多端并行验收
- 已重写 Phase 1 关键验收重点，明确收敛到：
  - macOS 可启动性
  - 桌面布局
  - 键盘流
  - Today / Inbox 主路径
  - 低打扰提醒

- 已定义当前最关键的 P0 / P1 门槛

- 当前代码库 **没有 macOS 平台工程**，P0-1 直接阻断

- 当前没有真实任务模型、状态管理、持久化，Today / Inbox 无法验收
