# Phase 1 QA Baseline — 首轮验收结构

## 1. 目标

把当前 Prism ToDo 的 Phase 1 从“仓库脚手架”收敛到“可执行验收”。

当前事实：
- 仓库已有 README、基础 `pubspec.yaml`、架构/计划文档
- `apps/mobile` 尚未生成
- 尚无可运行 App、CI、测试目录、测试数据约定
- PRD 仍未入库，因此本轮验收以“工程基线可运行、可分析、可测试、可继续开发”为主

---

## 2. 首轮验收范围

本轮只验收 4 类内容：

### A. 仓库与工程基线
- 目录结构符合 `apps/ + packages/ + docs/`
- Flutter workspace 可拉起
- 基础 lint / analyze / test 命令可执行
- 存在最小 CI 质量门

### B. 移动端最小可运行壳
- `apps/mobile` 已生成并可运行
- 存在明确入口 `main.dart`
- 首页可启动、无崩溃
- Debug 构建可在至少 1 个目标平台成功运行

### C. 架构边界最小落地
- `app_core / app_data / app_ui` 至少完成包骨架
- 依赖方向清晰，无明显反向耦合
- 路由、主题、基础配置位已建立

### D. QA 可执行基础设施
- 有测试目录与命名规范
- 有至少 1 条 smoke test
- 有验收清单与失败阻断规则
- CI 能对 PR 执行最小质量检查

---

## 3. 首轮验收结构（建议按 Gate 执行）

## Gate 0：准入检查（未通过不进入功能验收）

### G0-1 仓库结构
**门槛**
- 存在 `apps/`, `packages/`, `docs/`
- `apps/mobile` 已初始化
- `packages/app_core`, `packages/app_data`, `packages/app_ui` 已创建

**阻断条件**
- `apps/mobile` 不存在
- 包结构缺失，导致后续测试无法定位

### G0-2 工具链可用
**门槛**
- `flutter pub get` 成功
- `flutter analyze` 成功
- `flutter test` 可执行

**阻断条件**
- 任一基础命令无法运行
- 依赖解析失败

### G0-3 CI 基线
**门槛**
- PR 上自动执行 format / analyze / test（至少 analyze + test）
- CI 失败时禁止视为可验收

**阻断条件**
- 无 CI
- CI 只跑构建，不跑静态检查和测试

---

## Gate 1：可运行性验收

### G1-1 App 启动
**门槛**
- `apps/mobile` 启动到首页无 crash
- 首帧后无阻断性红屏/异常

**建议证据**
- 本地运行截图或录屏
- 启动日志

### G1-2 最小导航/壳层
**门槛**
- 存在 `MaterialApp` / Router 配置
- 存在默认首页（哪怕是 placeholder）
- 主题配置可集中管理

### G1-3 可测试入口
**门槛**
- Widget tree 可被测试挂载
- 入口层无强耦合外部服务（否则难以测试）

---

## Gate 2：架构与可维护性验收

### G2-1 包边界
**门槛**
- `app_core`: 仅放领域模型、常量、纯工具
- `app_data`: 数据源、仓储实现、DTO/adapter
- `app_ui`: 设计系统、共享 widget、theme
- `apps/mobile` 负责装配，不承载大段业务实现

**阻断条件**
- App 入口直接承载数据层细节
- 共享 UI 与业务逻辑混杂

### G2-2 依赖方向
**门槛**
- 不允许 `app_core` 依赖 `app_ui` / `app_data`
- 不允许形成循环依赖
- 依赖关系在文档中有最小说明

### G2-3 配置与环境隔离
**门槛**
- 至少预留 dev/prod 配置位或配置注入点
- 禁止把未来 API 密钥、endpoint 硬编码进 UI

---

## Gate 3：QA 基础设施验收

### G3-1 测试分层
**门槛**
- `test/` 至少存在以下分层之一：
  - unit
  - widget
  - smoke
- 命名规则明确，例如 `*_test.dart`

### G3-2 首条 smoke case
**门槛**
- 至少 1 条 smoke test 覆盖：App 可启动 + 首页关键文案/组件可见
- 该用例进入 CI

### G3-3 缺陷阻断规则
**门槛**
- P0/P1 缺陷定义清晰
- PR 若引入 P0/P1 风险，不得进入“可验收”状态

---

## 4. 首批必须拦截的 P0 / P1 风险与门槛

## P0（必须阻断上线/阻断进入下一阶段）

### P0-1 应用无法启动或启动即崩溃
**拦截门槛**
- Debug 环境无法稳定进入首页
- 首屏 crash / 红屏 / 主线程阻断

### P0-2 基础质量门不可执行
**拦截门槛**
- `flutter analyze` 失败
- `flutter test` 无法执行
- 依赖安装失败

### P0-3 CI 缺失或 CI 与本地标准脱节
**拦截门槛**
- 无 PR 自动检查
- 本地通过、CI 不可复现
- 关键分支允许绕过质量门合并

### P0-4 架构边界失控，导致无法继续测试
**拦截门槛**
- 入口层耦合外部服务，无法 mock
- 包依赖循环或核心包职责混乱
- 导致 smoke test 无法建立

## P1（允许继续开发，但必须尽快修复）

### P1-1 缺少最小 smoke test
**门槛**
- 若无 smoke test，本轮不得标记“QA ready”

### P1-2 缺少配置注入点
**门槛**
- 若后续 AI/网络能力会接入，但当前无环境配置位，标记为 P1

### P1-3 首页壳层存在明显不可维护问题
**门槛**
- 大量逻辑堆在 `main.dart`
- 路由、主题、启动装配未拆分

### P1-4 文档与代码脱节
**门槛**
- 目录/依赖方向与 `docs/planning`、`docs/architecture` 明显不一致

## 5. Dev 当前最需要补齐的测试前置项（Top 5）

### 1) 生成并提交 `apps/mobile` 最小 Flutter 应用
**为什么**
- 没有可运行 App，就没有真实验收对象

**完成标准**
- 包含 `lib/main.dart`
- 可 `flutter run`
- 首页可见稳定 placeholder

### 2) 建立 `packages/app_core`、`packages/app_data`、`packages/app_ui` 包骨架
**为什么**
- QA 需要依据边界判断“架构是否可测、是否可扩”

**完成标准**
- 每个 package 至少有 `pubspec.yaml` 与最小导出文件
- 依赖方向可说明

### 3) 补上最小测试与 smoke case
**为什么**
- 没有 smoke，就没有持续回归抓手

**完成标准**
- 至少 1 条 widget/smoke 测试
- 覆盖 App 启动与首页关键元素
- CI 自动执行

### 4) 补上 CI 工作流
**为什么**
- QA 验收不能依赖口头“本地跑过”

**完成标准**
- PR 自动跑 `flutter analyze` + `flutter test`
- 失败即红灯

### 5) 补充最小环境配置约定
**为什么**
- Prism ToDo 后续一定涉及环境差异/接口接入
- 现在不留注入点，后面测试会反复返工

**完成标准**
- 至少定义配置入口或环境变量读取方案
- 文档说明 dev/prod 如何切换

## 6. 建议的首轮测试用例清单（可立即落地）

### Smoke-01：应用可启动
- 前置：完成 `apps/mobile`
- 步骤：执行测试/运行 App
- 期望：首页渲染成功，无异常
- 优先级：P0

### Smoke-02：首页关键组件可见
- 前置：首页有标题/主按钮/占位内容
- 步骤：挂载根组件
- 期望：关键文本或组件可见
- 优先级：P1

### Arch-01：包依赖方向检查
- 前置：3 个 package 已建立
- 步骤：检查 imports/依赖说明
- 期望：无反向依赖/循环依赖
- 优先级：P0

### Eng-01：CI 质量门检查
- 前置：CI 已配置
- 步骤：触发 PR 检查
- 期望：analyze/test 正常执行并回传状态
- 优先级：P0

## 7. QA 结论口径（本轮）

在当前仓库状态下，项目**尚未达到 QA Ready**。

原因不是发现了业务缺陷，而是：
- 验收对象（可运行 App）尚未存在
- 自动化质量门尚未建立
- 测试入口与架构边界还停留在规划层

因此本轮 QA 的目标不是“验功能”，而是先把“可验收的最小基线”钉住。

---

## 8. 通过标准（建议作为本轮 Exit Criteria）

只有同时满足以下条件，才能进入下一轮功能验收：
- `apps/mobile` 已生成并可运行
- 三个 package 骨架存在且职责清晰
- `flutter analyze` / `flutter test` 可执行
- 至少 1 条 smoke test 已进入 CI
- PRD 或 MVP 范围文档已入库，便于下一轮做真实业务验收
